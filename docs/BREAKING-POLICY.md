# 破坏性变更政策（Breaking Change Policy）

> 状态：Accepted（2026-10）。本文是 31 项缺口实施期破坏性变更的**统一裁决规则**；
> 每一处契约推翻必须能指着本文的某个条款说"按第 N 条办理"。

## 1. 版本语义与本政策的适用范围

本 crate 发布 crates.io（2026-10 决策，废止早期「不发布」约定 C4/C7）；发布不改变下述 0.x 语义。在 0.x 阶段：

- **Minor 位 = 特性新增**，允许携带破坏性变更（0.x 惯例 + 无下游版本矩阵）；
- **Patch 位 = 修复**，不得改变公有行为；
- **Major 位 = 1.0 之后的破坏**。CHANGELOG 既有约定「Major 位（未发生）」自本文起
  具体化为：0.x 阶段破坏随 Minor 位发布，每处破坏单独成段标注。

## 2. 破坏分级

| 级别 | 定义 | 例 | 手续 |
|---|---|---|---|
| **T-扩展** | 公共 `#[non_exhaustive]` 枚举新增变体；新增属性槽位；新增 API | 新增 `PaintOp::Outline`、`PropertyId` 新变体 | 无破坏手续（宿主 match 必带通配臂已是契约）；CHANGELOG 特性段记录即可 |
| **T-签名** | 公共结构体字段/函数签名变更、行为可观察的默认值变更 | `Frame` 新增字段 | CHANGELOG「破坏性变更」段 + 一行迁移说明 |
| **T-契约** | 已文档化行为语义的推翻（即使编译不破） | 下节五处 | **ADR 先行**（含验收标准与迁移路径两节）+ CHANGELOG 破坏段 + FEATURES.md 注册表/偏差同步 + 受影响锁定测试显式更新并标注政策条号 |

## 3. 已预告的五处 T-契约破坏

1. **IFC 推翻 display:inline 契约化归一 Block**（第五批⑧；ADR-0011）：inline/
   inline-block 从「块级参与 + 告警」变真实行内参与；解析层归一告警在 IFC 落地帧
   起移除，宿主树需感知新行盒语义。
2. **结算 DAG 化改 settle_\* 收敛契约**（ADR-0012）：「上限 N 遍」→显式依赖求解；
   私有面重构，深层链路从「记偏差」变「精确」，B 级偏差条目随之消除。
3. **多重背景改 DisplayList 契约**（ADR-0013）：单背景一比一变层列表语义；
   `PaintOp` 变体签名扩展按 T-签名办理，宿主自定义转译器需适配。
4. **逻辑属性改布局映射契约**：公有面 additive（新槽位），映射内部转向属实现
   细节——按 T-扩展办理，映射行为变更在 FEATURES.md 偏差段记录。P9 现状补
   充：槽位编号自 P9-3 起，ListStyleType/Position/Image（173/174/175）占用
   ALL 尾部、动画描述符槽后移至 176..182——0.x 阶段 Slot 编号本身非公有契
   约（`slot()` 为 crate 内寻址），公有面 = `PropertyId` 枚举与 `ALL` 序
   列，追加式扩展不构成破坏；**1.0 冻结后新槽位只允许尾追加**（插入式中
   间编号即 T-扩展破坏，需按 §4 流程办理）。
5. **多样式表改 Epoch/失效语义**（ADR-0010）：`set_stylesheet` 替换语义永久保留，
   新增 add/remove 表接口；Epoch 从「整表版本」细化为「表集合版本」。

## 4. 破坏流程（每处 T-契约必走）

ADR 先行 → 实现带迁移注释 → CHANGELOG「### 破坏性变更（0.x Minor）」逐条
（破什么/为什么/怎么迁）→ FEATURES.md 同步（不留僵尸描述）→ 锁定测试更新标注
政策条号（如「破坏 3：多重背景」）。

## 5. 兼容层政策

- `set_stylesheet` 替换语义**永久保留**（语法糖，非兼容层）；
- 其余兼容 shim 生存期 = 1 个 Minor 位，CHANGELOG 标注移除版本，到期删除；
- 不为「依赖错误行为」的宿主代码提供兼容——文档化行为才受 Hyrum's Law 保护。
